# Требования

## User Stories

### US-01. Анализ тональности отзыва

Как пользователь,
я хочу отправить текст отзыва и получить его тональность,
чтобы быстро понять общую оценку своего сообщения.

Критерии приёмки:

- система принимает непустой текст отзыва;
- после обработки отображается одна из категорий: положительная, нейтральная или отрицательная;
- если текст пустой, система показывает сообщение об ошибке.

### US-02. Просмотр уверенности модели

Как пользователь,
я хочу видеть уровень уверенности модели,
чтобы понимать, насколько надёжен результат классификации.

Критерии приёмки:

- вместе с категорией отображается значение уверенности;
- уверенность выражается в процентах;
- если модель не может обработать текст, уверенность не отображается.

### US-03. Сохранение результата анализа

Как аналитик,
я хочу сохранять результаты анализа отзывов,
чтобы позже изучать обратную связь пользователей.

Критерии приёмки:

- после успешного анализа результат сохраняется в системе;
- для каждого результата доступны текст отзыва, категория и уверенность;
- пользователь получает подтверждение успешного сохранения.

## Use Case

### UC-01. Определение тональности отзыва

**Актор:** пользователь.

**Цель:** определить тональность отправленного отзыва.

**Предусловие:** пользователь открыл страницу анализа отзывов.

**Основной сценарий:**

1. Пользователь вводит текст отзыва.
2. Пользователь нажимает кнопку «Проанализировать».
3. Система проверяет, что текст не пустой.
4. Система передаёт текст в ML-модель.
5. ML-модель определяет тональность и уровень уверенности.
6. Система отображает пользователю категорию и уверенность.
7. Система сохраняет результат анализа.

**Альтернативный сценарий:**

Если текст отзыва пустой или не может быть обработан, система сообщает об ошибке и не сохраняет результат.

**Результат:** пользователь видит определённую тональность отзыва или получает сообщение об ошибке.
